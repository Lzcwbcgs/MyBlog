## 一、工作方式（约定）

| 项 | 约定 |
|---|---|
| 复刻忠实度 | **完全一致，连坑一起复刻**。文件路径 / 包名 / 函数名 / 结构体名 / 注释风格全部对齐原版，以便逐文件 diff |
| 谁敲代码 | **你敲，我讲 + review**。我给完整代码 + 逐段讲解，你跟着敲 |
| 测试节奏 | **每个阶段配冒烟测试**，保证「随时可运行」 |
| 归档约定 | 你说「继续」时，我先把上一节整理成 `docs/` 下的 md，再讲新内容 |
| 工作目录 | 后端一律从 `gin-blog-server/cmd/` 运行（`../config.yml` 和 `gvb.db` 都相对它解析） |
| 文档命名 | `docs/P<阶段>-<序号>-<标题>.md`，序号在阶段内连续 |
| 代码命名 | 模块名 `gin-blog`；`internal/global` 的包名声明为 `g`，import 时用别名 |

## 十一、P7 · Redis 计数与缓存

**目标**：区分 Redis 的两种角色，并为「Redis 是唯一数据源」的场景补上备份链路
**验收**：点赞 → 重启服务 → 计数不归零

| 节 | 标题 | 交付文件 | 状态 |
|---|---|---|---|
| P7-1 | 读穿缓存与 TTL | `internal/handle/cache.go` | ⬜ |
| P7-2 | 计数的落库备份模型 | `internal/model/counter_snapshot.go` | ⬜ |
| P7-3 | 落库与回填 | `internal/counter.go` | ⬜ |
| P7-4 | 接入 main.go（优雅关闭） | `cmd/main.go`（`r.Run` → `http.Server`） | ⬜ |
| P7-5 | 验收与数据一致性 | — | ⬜ |

**各节要点**

- **P7-1**：`cacheTTL`；**哪些键能加 TTL、哪些绝对不能**（DB 是真源的可以，Redis 是唯一数据源的不行）；`hashCounts` / `zsetCounts` 的批量读（避免 `HGetAll` 拉全表）
- **P7-2**：`CounterSnapshot` 的 `(Key, Member)` 复合主键
- **P7-3**：**三种键类型不能一把抓**（Hash / ZSet / String，原版踩过 `WRONGTYPE`）；`RestoreCounters` **只补 Redis 里不存在的键**（活数据优先，一律不覆盖）
- **P7-4**：**`r.Run()` 换成 `http.Server` + `signal.NotifyContext`**；服务放 goroutine、主线程等信号、信号来了先 `FlushCounters` 再 `Shutdown`；`errors.Is(err, http.ErrServerClosed)` 的意义
- **P7-5**：验证「清 Redis 后重启，计数能从备份恢复」
