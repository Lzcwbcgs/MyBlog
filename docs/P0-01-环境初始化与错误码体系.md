## 第 1 节 · 初始化模块与目录

### 1.1 为什么先做这一步

Go 和 Node / Python 不一样：**没有「先装依赖再写代码」的流程**。

Go 是反过来的 —— 「你代码里 import 了什么，`go mod tidy` 就去拉什么」。所以顺序是：

1. 先 `go mod init` 声明模块身份（这个名字会变成所有内部 import 的前缀）
2. 建目录
3. 写代码，import 什么就有什么

模块名 `gin-blog` 决定了后面所有内部导入长这样：

```go
import g "gin-blog/internal/global"
```

### 1.2 动手

```bash
cd D:/code/gocode/blog/MyBlog/gin-blog-server
go mod init gin-blog
```

输出应为 `go: creating new go.mod: module gin-blog`。

```bash
mkdir -p internal/global cmd
```

此时的目录：

```
gin-blog-server/
├── go.mod
├── BUILD_ROADMAP.md      # 整体路线图
├── internal/
│   └── global/
└── cmd/
```

### 1.3 关于 `internal/` 的补充

Go 有条硬规则：**`internal` 目录下的包，只有以它父目录为根的子树里的代码能 import**。

这里路径是 `gin-blog/internal/global`，父目录是 `gin-blog/`，所以只有 `gin-blog` 模块自己能用它。外部模块引用会**编译失败**，不是 warning，是 error。

这比 Java 的 `package-private`、或者靠约定分层的做法都硬 —— 它把「这些是实现细节」变成了语言机制强制的事实。

**实践细节**：`internal` 不一定非要在根目录，可以放在任意层。比如 `internal/model/internal/xxx` 就把可见范围收窄到了 `internal/model/` 及其子包。原版只在根上放了一个 `internal`，因为整个后端都算实现细节，只有 `cmd/` 是入口。

## 第 2 节 · `internal/global/result.go`

### 2.1 为什么第一个写它

因为它是**整个项目里唯一零依赖的文件**。后面写的每一个 handler 都要返回错误，而返回错误需要错误码。先把它立起来，后面才有「统一的语言」。

这个文件要解决的核心问题是：**业务错误怎么表达**。

### 2.2 完整代码

新建 `internal/global/result.go`：

```go
package g

import (
	"fmt"
)

const (
	SUCCESS = 0   // 成功业务码
	FAIL    = 500 // 失败业务码
)

// 自定义业务 error 类型
type Result struct {
	code int
	msg  string
}

func (e Result) Code() int {
	return e.code
}

func (e Result) Msg() string {
	return e.msg
}

var (
	_codes    = map[int]struct{}{}   // 注册过的错误码集合, 防止重复
	_messages = make(map[int]string) // 根据错误码获取错误信息
)

// 注册一个响应码, 不允许重复注册
func RegisterResult(code int, msg string) Result {
	if _, ok := _codes[code]; ok {
		panic(fmt.Sprintf("错误码 %d 已经存在，请更换一个", code))
	}
	if msg == "" {
		panic("错误码消息不能为空")
	}

	_codes[code] = struct{}{}
	_messages[code] = msg

	return Result{
		code: code,
		msg:  msg,
	}
}

// 根据响应码获取响应信息
func GetMsg(code int) string {
	return _messages[code]
}

var (
	OkResult   = RegisterResult(SUCCESS, "OK")
	FailResult = RegisterResult(FAIL, "FAIL")
)

var (
	ErrRequest  = RegisterResult(9001, "请求参数格式错误")
	ErrDbOp     = RegisterResult(9004, "数据库操作异常")
	ErrRedisOp  = RegisterResult(9005, "Redis 操作异常")
	ErrUserAuth = RegisterResult(9006, "用户认证异常")

	ErrPassword     = RegisterResult(1002, "密码错误")
	ErrUserNotExist = RegisterResult(1003, "该用户不存在")
	ErrOldPassword  = RegisterResult(1010, "旧密码不正确")
	// 登录失败统一返回这个, 不区分"用户不存在"和"密码错误", 否则靠错误码就能枚举用户名
	ErrLoginFail   = RegisterResult(1004, "用户名或密码错误")
	ErrLoginLocked = RegisterResult(1005, "登录失败次数过多, 请稍后再试")

	ErrTokenNotExist    = RegisterResult(1201, "TOKEN 不存在，请重新登陆")
	ErrTokenRuntime     = RegisterResult(1202, "TOKEN 已过期，请重新登陆")
	ErrTokenWrong       = RegisterResult(1203, "TOKEN 不正确，请重新登陆")
	ErrTokenType        = RegisterResult(1204, "TOKEN 格式错误，请重新登陆")
	ErrTokenCreate      = RegisterResult(1205, "TOKEN 生成失败")
	ErrPermission       = RegisterResult(1206, "权限不足")
	ErrForceOffline     = RegisterResult(1207, "您已被强制下线")
	ErrForceOfflineSelf = RegisterResult(1208, "不能强制下线自己")
	ErrUserDisabled     = RegisterResult(1209, "该账号已被禁用")

	ErrFileUpload  = RegisterResult(9100, "文件上传失败")
	ErrFileReceive = RegisterResult(9101, "文件接收失败")
	ErrFileType    = RegisterResult(9102, "只支持上传图片")
	ErrFileSize    = RegisterResult(9103, "文件大小超出限制")
	ErrImportType  = RegisterResult(9104, "只支持导入 Markdown 文件")

	ErrTagHasArt  = RegisterResult(4003, "删除失败，标签下存在文章")
	ErrCateHasArt = RegisterResult(3003, "删除失败，分类下存在文章")

	ErrResourceNotExist    = RegisterResult(6002, "该资源不存在")
	ErrResourceUsedByRole  = RegisterResult(6003, "该资源正在被角色使用，无法删除")
	ErrResourceHasChildren = RegisterResult(6004, "该资源下存在子资源，无法删除")
	ErrMenuNotExist        = RegisterResult(6006, "该菜单不存在")
	ErrMenuUsedByRole      = RegisterResult(6007, "该菜单正在被角色使用，无法删除")
	ErrMenuHasChildren     = RegisterResult(6008, "该菜单下存在子菜单，无法删除")

	ErrSendEmail      = RegisterResult(6101, "发送邮件失败")
	ErrCodeNoexit     = RegisterResult(6102, "Code不存在 请重新注册")
	ErrParseEmailCode = RegisterResult(6103, "解析邮件Code失败 请重试")
	ErrUserExist      = RegisterResult(6104, "该邮箱已经注册 请重新注册")
)
```

### 2.3 逐段讲解

#### ① 为什么 `code` / `msg` 是小写，却又要写 `Code()` / `Msg()` 方法

```go
type Result struct {
	code int      // 小写 → 包外不可见
	msg  string
}
func (e Result) Code() int { return e.code }
```

小写 = 只有 `package g` 内部能直接读写。外部（`handle`、`middleware`）只能通过 `Code()` / `Msg()` **读**，不能**改**。

这是 Go 里实现「只读字段」的标准手法 —— Go 没有 `readonly` 关键字，靠的是「字段不导出 + 导出 getter 方法」。

**为什么不干脆都大写？** 因为 `Result` 会出现在很多地方，如果 `code` 可写，某处一个手滑 `r.code = 0` 就能把错误码改成成功码。让它在类型系统层面就改不了，比靠纪律可靠。

#### ② 注册表 + `panic`

```go
func RegisterResult(code int, msg string) Result {
	if _, ok := _codes[code]; ok {
		panic(fmt.Sprintf("错误码 %d 已经存在，请更换一个", code))
	}
	...
}
```

关键在于**这行代码什么时候执行**：

```go
var ErrRequest = RegisterResult(9001, "请求参数格式错误")
```

Go 的**包级变量初始化**发生在 `main()` 之前。所以 `package g` 被 import 的那一刻，`result.go` 里所有 `var` 都会按顺序执行一遍。

如果两个错误码写重了 → 程序**启动前就 panic 退出**，而不是跑到某个业务分支才行为诡异。

> **这是个通用的设计模式**：初始化期能发现的错误，绝不留到运行期。
>
> 对比两种做法：
> - 返回 `error`：`var ErrX = Register(9001, "...")` 你得写 `ErrX, err := ...`，包级变量没法这么写，而且没人会检查这个 err
> - `panic`：启动即失败，而且失败信息直接告诉你哪两个码撞了
>
> 原版选择 panic 不是因为「懒得处理错误」，是因为**这个错误只有在开发期出现，运行期永远不会发生**。

#### ③ 错误码的分段规律

| 段位 | 含义 | 例子 |
|---|---|---|
| `0` / `500` | 成功 / 通用失败 | `OkResult` / `FailResult` |
| `1xxx` | 用户与认证 | `1002` 密码错误、`1005` 登录锁定 |
| `12xx` | Token 相关 | `1201` 不存在、`1202` 过期、`1209` 账号禁用 |
| `3xxx` / `4xxx` | 内容实体 | `3003` 分类下有文章、`4003` 标签下有文章 |
| `6002~6008` | 权限体系 | 资源/菜单的「不存在」「被占用」「有子节点」 |
| `6101~6104` | 邮件注册 | 发信失败、验证码失效 |
| `9xxx` | 系统级 | `9001` 参数错、`9004` 数据库、`9005` Redis |

**为什么这个分段重要？** 因为前端要按码分流处理：

```js
// gin-blog-admin/src/utils/http.js —— 响应拦截器
if (code === 1201) authStore.toLogin()
else if ([1202, 1203, 1207, 1209].includes(code)) authStore.forceOffline()
```

前端不需要认识每一个码，只需要知道「`12xx` 这一片是登录态问题」。**分段是前后端之间的隐式契约**。

#### ④ 一个安全细节

```go
// 登录失败统一返回这个, 不区分"用户不存在"和"密码错误", 否则靠错误码就能枚举用户名
ErrLoginFail = RegisterResult(1004, "用户名或密码错误")
```

如果分成 `1003 用户不存在` + `1002 密码错误`，攻击者就能用脚本批量试用户名 —— 返回 `1003` 说明这个账号不存在，返回 `1002` 说明存在。

**这是错误码设计里的安全考量**，不是「懒得分」。

注意原版**同时保留了** `ErrUserNotExist = 1003` —— 它仍用在别的地方（比如 token 里的用户被删了），只是**登录路径上不准用它**。

#### ⑤ `_codes` 和 `_messages` 为什么要两张表

```go
_codes    = map[int]struct{}{}   // 只用来判重
_messages = make(map[int]string) // 用来查消息
```

`_codes` 的值类型是 `struct{}` —— Go 里的**零大小类型**，不占内存。这比 `map[int]bool` 省内存，表达「我只关心键在不在」也更准确。

这是 Go 惯用法，你会在标准库和很多项目里反复看到 `map[T]struct{}`。

## 本节留下的伏笔

- `Result` 只是「错误的表达」，还没有「错误的返回」。**怎么把它变成 HTTP 响应**是 P1 `handle/base.go` 的事。
- 错误码表里有一半现在用不上（`3003` 分类、`6101` 邮件等），留着是因为**它们是一个整体**，拆开写反而看不出分段规律。
